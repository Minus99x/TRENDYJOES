# Objective 31Q — authenticated portable acquisition evidence across witness epochs

**Offline diagnostic prototype only. No Shopify integration, customer data, checkout, manufacturing, production, network service or operational authorization.**

`verifyOfflineAcquisitionCrossEpochAuthenticatedEvidence(args)` from `src/offline-acquisition-authenticated-cross-epoch.mjs` composes the existing 31P witness-policy rotation and cross-epoch signed-branch verifier with the original 31L/31M/31N underlying evidence checks. It accepts 31P `policies`, `transitions`, `branches`, `registryId`, `nowMs`, `trustedAnchor`, `expectedGenesisPolicyDigest`, `expectedFinalPolicyDigest`, and `expectedFinalEpoch`, plus independently sourced `retentionTrust`, `forensicTrust`, and `branchEvidence`.

`branchEvidence` is an array parallel to `branches`. For **every** index entry of every branch (including common prefixes), provide exactly `{manifest,sessionEvents}`. The `sessionEvents` array must contain the complete BEGIN/PRE/POST records in sequence, exported from the local 31M acquisition session directory. A missing, partial or extra evidence record fails closed. All trusted keys, external policy/head pins, and time must originate from the reviewer independently, **not** from an archive under review.

The verifier first authenticates the complete signed 31P rotation and 31O index-attestation histories, then verifies that each manifest matches its indexed SHA-256 snapshot digest and independently pinned retention/forensic heads. It calls the existing 31L forensic/retention verifier to validate signed PRE/POST receipts and all included forensic bundle records. Finally, it verifies the session record chain, BEGIN identity and head bindings, PRE/POST byte-level payload equivalence, and the session digest pinned inside the signed index record. Witness keys may not overlap forensic reviewer/witness or retention keys. The result contains `verifiedEvidenceRecords`, `underlyingRetentionSignaturesVerified`, `underlyingForensicEvidenceVerified`, and `sessionHashesBoundToSignedIndex`; it never authorizes retry, ACK, manufacture or deployment.

**Critical security limits:** Session journal records are hash-chained but **not themselves digitally signed**. Their integrity is authenticated only through the separately quorum-signed index history and independent external anchors. Receipt signatures prove key possession and attestations, not that a physical acquisition observation occurred. A valid signed fork is evidence, not a safe choice of branch. Zero-event forensic bundles are cryptographically valid empty evidence; they are not evidence of any production operation. This does not provide independent witness deployment, secure private-key storage, trusted timestamps, offsite/WORM retention, remote concurrency control, or atomic multi-resource recovery. No hosted Shopify identity, customer authorization, order placement or manufacturing approval has been tested.

Test with Node 22.16.0: `node --test tests/objective31q-authenticated-cross-epoch.test.mjs` then `node --test --test-concurrency=4 tests/*.test.mjs`.
