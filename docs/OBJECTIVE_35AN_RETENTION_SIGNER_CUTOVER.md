# Night Watch Objective 35AN — dual-signed offline retention signer cutover

**Version v0.30.136. Local-only evidence protocol; no Shopify reads/writes.**

This module extends 35AM receipt verification with an explicit **old + new Ed25519 signer cutover**. The issuer produces a canonical, domain-separated dual-signed transition, identifying the stream, successor sequence, old receipt hash, first new receipt hash, observed cutover time and both public-key fingerprints. Both signing keys must be distinct. The signed transition has `authority:'NONE'` and grants no production or cart/order permissions.

`createOfflineRetentionKeyRotation(...)` is an **issuer-side** primitive. Signing keys must never be embedded in editor/browser bundles. `verifyOfflineRetentionKeyRotation({oldReceiptBytes,newReceiptBytes,rotationBytes,externalPins,oldPublicKey,newPublicKey})` verifies both signatures and delegates each receipt window to 35AM's signature, canonical-body, expiry, sequence, independent checkpoint and hash-chain verification. The old window may be a complete genesis window or an append extension; the new window **must** be an append window anchored to the old window's pinned head. Pruned old windows are not accepted in this first cutover contract.

The `externalPins` object is **independently authenticated**, not obtained from the transition or receipt transport. It must have exactly `{oldPins,newPins,expectedRotationSha256}`. Each window's pins have the exact 35AM schema and a **matching trustedNowMs**. The transition hash must match the independent `expectedRotationSha256`; both public keys must match the separately pinned signer fingerprints; the successor receipt must be at `old.expectedHead.sequence+1`, reference that exact prior hash, and have an observed time strictly after the last old receipt and exactly equal to the transition's cutover time. All retained receipts must be unexpired against the same supplied clock. The verifier rejects extra fields, getters in pin structures, noncanonical JSON/base64url, key substitutions, duplicate/reordered/truncated windows, stale/forked heads and unpinned transitions.

**Important limits:** Independently authenticated inputs are a caller obligation, not implemented external pin custody. This protocol does not revoke old keys globally, prevent a compromised signer from making undisclosed forks, establish multi-host consensus, verify historical 35AL issuer epoch provenance, or attest a real trusted clock. A cutover verified against an attacker-controlled pin set provides no security. No hosted auth, Shopify staging, checkout, production, GLB approval or customer data are involved. Output explicitly marks `independentlyCustodied:false`, `trustedClockIndependentlyVerified:false`, `authorizesProduction:false`.

Reproduce: `node --test tests/objective35an-retention-key-rotation.test.mjs` and `npm test` (or run every `tests/*.test.mjs` separately with bounded timeouts and retain TAP evidence). Then `npm run preview:assets:check`, `npm run preview:static:assets:check`, `npm run preview:staging:check`, `node scripts/build-main-staging-reconciliation.mjs --check`. Main Engineering's protected staging files remain a separate manual reconciliation gate.
