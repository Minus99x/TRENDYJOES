# Objective 33N — read-only filesystem acquisition receipts (offline only)

This optional Linux-only module acquires **actual canonical 33J record bytes** from an existing local inventory directory. It opens the inventory directory with `O_DIRECTORY | O_NOFOLLOW`, verifies independently retained directory `dev`/`ino` identity and restrictive permissions, reads each expected record through a directory-file-descriptor-anchored `/proc/self/fd/<fd>/<name>` path with `O_NOFOLLOW | O_NONBLOCK`, rejects symlinks, hardlinks, nonregular files, unsafe modes/ownership, missing or extra inventory entries, uncertain `.pending.json` commits, and byte/digest/head mismatches. Before and after reading, it compares file descriptors and directory entries, including device, inode, size, nanosecond `mtime` and `ctime`, and refuses observed TOCTOU races. **No files are created, modified, deleted, repaired, or recovered by the module.** `checkpoint` is an optional test-only callback to simulate races.

A caller provides externally retained directory pin, 33M-style consecutive `recordPins`, from/to inventory heads, namespace, journal scope, host/observer IDs, a locally held Ed25519 private signing key, caller-supplied observation time and expiry, and a nonce. `acquireOfflineConflictInventoryRecordsReadOnly` returns acquired `Buffer` records and an Ed25519-signed canonical JSON receipt. `verifyOfflineConflictInventoryAcquisitionReceipt` checks the receipt signature against a **separately supplied pinned public key**, the supplied bytes and all external pins, scope, host/observer, time window, and caller-supplied replay histories. The verifier does **not** persist replay state.

**Critical separation:** the receipt proves only that a specified private key signed a claim about local file descriptors and bytes observed by this process under its trust assumptions. A compromised local host or witness key can lie; there is no remote-host interrogation, independent witness, protected key store, trusted clock, immutable storage, cross-host consensus, durable replay registry, global history guarantee, or proof of historical prefix. The module validates canonical 33J envelope shape, local hash chain and pinned byte digests; it does **not** independently validate embedded reviewer/observer signatures. For that, pass the returned `records` separately to Objective 33M `verifyOfflineConflictInventoryRecordEvidence` with independently pinned signed host receipts and the matching record pins. Neither verifier authorizes production, recovery, cart, checkout, Shopify changes, or customer data access.

A caller must preserve the exact signed receipt bytes and independent pins outside the inspected directory. A signed receipt is not an independently witnessed publication and cannot be treated as one. Symlinked ancestors, directory replacement, stale pins, races, or untrusted file metadata cause fail-closed rejection where detectable. Filesystem-level malicious kernel behavior and writes after the observation cannot be excluded.

Reproduce focused tests with `node --test tests/objective33n-filesystem-acquisition.test.mjs` and full regression with `npm test` under Node 22.16.0. The 32 new tests exercise actual Linux file descriptors, valid Ed25519 receipts, forged and substituted signatures, scope and identity substitution, expiry, replay, omitted/extra records, uncertain commits, symlinks, hardlinks, unsafe permissions, stale record pins, historical rollback, noncanonical JSON, and induced TOCTOU/directory replacement.

No Shopify reads/writes, hosted auth, deployment, production data, paid services, or other projects.
