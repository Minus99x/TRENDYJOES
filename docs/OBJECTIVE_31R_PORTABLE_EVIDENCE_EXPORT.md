# Objective 31R — portable, bounded acquisition evidence transport

Status: **offline prototype only**. This is a deterministic **transport** format, not a signature, attestation, source-of-truth assertion, Shopify authentication, manufacturing authorization, or proof of physical observation.

`src/offline-acquisition-evidence-export.mjs` exports:

- `createOfflineAcquisitionEvidenceExport({rootDirectory, acquisitionId, relativePaths})`: read-only collection from an owner-private Linux directory. The caller must explicitly enumerate all source paths. The four required canonical paths are `manifest.json`, `session/0001.json`, `session/0002.json`, and `session/0003.json`; optional auxiliary JSON paths are `evidence/<lowercase-slug>.json`. File paths are sorted deterministically. Files and intermediate directories must not be symlinks; files must be owner-private, single-link regular files. The collector double-reads the files and rejects a changed root or differing bytes across passes. `injectFault` exists only for deterministic adversarial testing.
- `verifyOfflineAcquisitionEvidenceExport({bytes, expectedDigest, expectedAcquisitionId})`: requires a **separately retained trusted SHA-256 digest** and acquisition ID. It verifies the exact canonical file table, offsets, per-file SHA-256, whole payload SHA-256, bounded length, strict JSON serialization, acquisition ID and BEGIN/PRE/POST structural bindings. It returns parsed manifest and session records for subsequent independent cryptographic review, plus an explicit `EXTERNALLY_PINNED_TRANSPORT_ONLY` classification.

Wire format: ASCII `TJ-OFFLINE-ACQUISITION-EVIDENCE-EXPORT-1\n`, unsigned big-endian 32-bit header byte count, canonical compact UTF-8 JSON header (`schema`, `acquisitionId`, sorted `files` entries of `path`/`offset`/`size`/`sha256`, `payloadBytes`, `payloadDigest`), then concatenated canonical JSON bytes in that exact order. Maximum 64 files, 12 MiB/file, 32 MiB total payload, 16 KiB header. No ZIP extraction or destination writes occur, eliminating archive traversal on import. The dedicated export root and subdirectories are enumerated before and after collection: unexpected, omitted, or pending files fail closed. Only a private regular `session/.session-lock` is permitted as non-evidence. No unlisted evidence is silently skipped. The independent digest covers **all** bytes, including framing.

**Critical security boundary:** If an attacker can replace the archive *and* the independently retained expected digest, transport verification cannot detect it. A locally owned filesystem and two reads are not an atomic snapshot and do not defend against all same-UID adversarial races. This format does not individually sign the session journal, verify underlying retention or forensic signatures, prove timestamps or offsite retention, or verify every historical branch. After import, feed `manifest` and `sessionEvents` to Objective 31Q's `verifyOfflineAcquisitionCrossEpochAuthenticatedEvidence` along with all independent witness/retention/forensic trust, pins, policy transitions, and complete branch evidence. Do not infer 31Q verification from 31R's `verified:true` transport result. Neither module authorizes recovery, ACK, checkout, production, or deployment.

Reproduce: `node --test tests/objective31r-evidence-export.test.mjs` and `node --test --test-concurrency=4 tests/*.test.mjs`. No network, customer data, Shopify writes, dependencies or signing keys are required.
