# Objective 33O — pinned multi-session acquisition-receipt registry (offline only)

This Linux-local, **single-host** module durably admits signed Objective 33N filesystem-acquisition receipts across successive, contiguous inventory observation sessions. It requires an **independently retained registry head and registry-directory device/inode pin on every call**. The registry genesis is cryptographically bound to namespace, journal scope, host identity, observer identity, separately supplied Ed25519 witness public key and the independently pinned initial inventory head. The caller is responsible for preserving and advancing those pins **outside** the registry's filesystem. Without externally retained pins, an attacker able to rewrite both history and expected pins can evade rollback detection.

`createOfflineConflictInventoryAcquisitionRegistry({directory,namespaceId,journalScopeDigest,hostId,observerId,expectedObserverPublicKey,initialInventoryHead})` returns `genesisHead`, `inspect({expectedHead,expectedRegistryDirectoryPin})` and `accept({receiptBytes,records,recordPins,expectedDirectoryPin,expectedFromHead,expectedToHead,nowMs,expectedHead,expectedRegistryDirectoryPin})`. The caller creates a private 0700 directory and retains its `dev` and `ino` independently. The receipt's `expectedDirectoryPin` refers to the *source inventory directory*; `expectedRegistryDirectoryPin` refers to the *new acceptance registry directory*. These are deliberately distinct.

Every admission re-verifies the canonical Ed25519-signed 33N receipt, actual supplied record bytes, pinned source directory identity, record byte hashes, inventory head continuity, host/observer/namespace/scope, caller-supplied time window, and durable seen-nonce/receipt-digest history. The journal retains the receipt, supplied record bytes, verification pins, nonce, and digest for **full historical signature re-verification** on every inspection or admission. New sessions must start at the prior accepted session's inventory head; gaps, forks, stale registry heads, duplicate nonces and receipt digests fail closed. Journal records form an append-only SHA-256 predecessor chain with a 64-record bound and a 3 MB per-record limit.

The registry uses restrictive Linux file permissions, `O_NOFOLLOW` reads, file descriptor versus directory entry identity and nanosecond metadata comparisons, an atomic mkdir lock, exclusive `.pending.json` creation, file `fsync`, directory `fsync`, hardlink publication and final directory `fsync`. SIGKILL can leave a lock and/or pending file. **There is intentionally no automatic cleanup, repair, rollback, or recovery.** An authorized external operator must independently adjudicate uncertain state; deleting a lock without reviewing pending data is not an endorsed production procedure. Tests explicitly remove orphan locks solely to assert the subsequent fail-closed boundary.

The signed receipt is an observer assertion, **not independent proof of remote disk truth**. Stored pins are cryptographically linked to the independently retained registry head but are not independently published trust anchors. Caller-supplied `nowMs` is not a trusted timestamp. This module is not multi-host consensus, immutable offsite storage, hosted customer authentication, distributed atomic recovery, manufacturing authorization, cart/checkout authorization, or production-ready Shopify integration. It never reads or writes Shopify.

Reproduce on Node 22.16.0: `node --test tests/objective33o-acquisition-registry.test.mjs`; `npm test`. The 30 adversarial tests cover authentic two-session continuity, forged signatures, cross-scope substitutions, stale external pins, record tampering, omitted/rolled-back history, duplicate nonces across sessions, directory inode replacement, symlink/hardlink/permissions, independent Node processes racing on one head, and real SIGKILL at three durable commit boundaries.
