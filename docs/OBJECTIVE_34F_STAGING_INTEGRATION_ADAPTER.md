# Objective 34F — staging-only preview adapter and offline customer-flow acceptance

The `integrations/shopify/snippets/tj-studio-preview-entry.liquid` and companion CSS are **offline merge-ready source**, NOT uploaded or installed in Shopify. They offer seven conceptual product families and a strict, default-disabled preview route. Main Engineering must first install and independently verify a functional `/pages/design-works-preview` page in the UNPUBLISHED staging theme; only then may it pass `preview_route_verified: true` to the snippet. This boolean is a local integration gate, **not** evidence of hosted authentication, backend availability, manufacturing approval or checkout.

`src/staging-preview-adapter.mjs` is the strict contract: exact route, one allowlisted `product` query, no tokens, variants, price, cart, account or checkout data. No external hosts or loopback server links are ever constructed. The snippet intentionally cannot expose the local development HTTP server. The Liquid adapter is not the full Studio; Main must independently package, host and validate the editor and its browser module graph, remove/replace local-only APIs, and complete native Shopify theme QA. Default cards remain inert to avoid broken links.

The executable Node HTTP acceptance tests exercise the actual local loopback gateway/editor resources, local save/read/revision contract, cross-owner denial, preview-summary privacy, negative commerce routes, and staging adapter. These are not Chromium interaction or native Shopify staging acceptance. No Shopify writes, no deployment, no real customer data, no prices or orders.
