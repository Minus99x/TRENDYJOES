# Objective 32E — signed and independently pinned replay-head audit (offline)

Release: v0.30.32. This module is a read-only offline verifier, not a service, deployable custody layer or Shopify integration.

## Protocol

`offlineReplayHeadCheckpointSigningBytes(body)` emits domain-separated deterministic signing bytes for a strictly shaped checkpoint: registry ID, externally pinned genesis, terminal replay digest, committed decision count, full audit-history digest, previous checkpoint digest, monotonically externally expected sequence, asserted issuance time and auditor-policy digest.

`offlineReplayHeadCheckpointDigest(checkpoint)` commits to the **entire signed envelope**, including the exact auditor signatures. It must be retained **independently** of the local replay directory and the audit bundle; callers must not derive the expected pin from the same untrusted bundle during verification.

`offlineReplayHeadAuditorPolicyDigest` pins a distinct majority-quorum Ed25519 auditor key roster. No private key is held or generated by production module code. `offlineReplayHeadAuditHistoryDigest(items)` binds ordered exact replay commit records, original signed decisions, report bytes, report pins, reviewer keys/policies, and historical observation timestamps. The public-key roster is included as SPKI DER key bytes in the signed history commitment.

`verifyOfflineReplayHeadCheckpoint` checks independent external genesis, current checkpoint, previous checkpoint and auditor-policy pins and expected checkpoint sequence. It verifies auditor quorum signatures, full ordered history digest, every 32C supervisory decision signature and report pin, 32D replay predecessor/next digest, exact decision ID/nonce/decision digest binding, and final replay head. Historical signed decisions are verified at an auditor-attested observation timestamp inside their 5-minute window, but **there is no independent trusted time source**. The verifier returns explicit `authorizesRemediation:false`, `authorizesCheckout:false`, `productionApproved:false`, `externalPinPublicationVerified:false`, and `trustedTimestampVerified:false`.

## Crash / publication boundary

An actual child-process SIGKILL after the 32D durable hardlink/commit sync leaves unresolved staging evidence. Independent supervisory finalization is still required by 32D. Even after local recovery, 32E **will not** accept an absent external checkpoint digest. Locally signing a checkpoint is not proof that any remote immutable witness has received or retained it. This module never publishes or persists pins, executes remediation, touches Shopify, or performs automatic recovery.

## Reproduction

```sh
node --version
node --test tests/objective32e-replay-head-checkpoint.test.mjs
npm test
```

Security assumptions: independent external checkpoint pin and previous-checkpoint anchor, protected auditor and reviewer signing keys, honest separately attested observation timestamps, and authentic inputs supplied by the operator. A compromised auditor quorum or caller-supplied forged 'external' pin defeats this trust boundary. The verifier does not inspect local file metadata or prove remote custody; use 32D's separate filesystem scanner for that. Same-UID hostile filesystem races, distributed storage, real power-loss durability, offsite retention, hosted auth, physical calibration, real checkout and atomic cross-resource recovery remain unproven.
