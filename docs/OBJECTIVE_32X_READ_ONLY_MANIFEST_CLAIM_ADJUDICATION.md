# Objective 32X — interrupted manifest-claim inspection (offline only)

This is **read-only evidence inspection**, not recovery, completion, retry, or an authorization to delete `.pending.json`. The 32W journal still blocks all ordinary inspection/claims while a pending file exists. The new opt-in `adjudicateInterruptedClaimReadOnly()` authenticates a time-bounded, exact state-specific `inspect-only` decision signed by Ed25519 majorities of **two distinct, independently pinned reviewer rosters**. Both roster pins, decision digest, prior journal head, and raw pending-byte digest must come from outside the local journal. The method reads existing evidence under a single-host lock and does not create or delete journal records or pending markers.

For `pending-only`, it verifies the complete prior chain against the externally pinned prior head and validates the pending canonical record, digest, sequence, and replay uniqueness. For `linked-pending`, it additionally verifies the final journal entry is the same inode and bytes as the pending marker and the previous head matches the independently pinned prior head. Both states remain unresolved and fail closed. Unknown files, unsafe permissions, symlinks, unexpected hardlinks, conflicting records, forked/rolled-back chains, forged signatures, expired authorization, and mismatched external pins are rejected.

The result describes **locally observed evidence only**; no remote witness, hosted authentication, trusted timestamp, independent monotonic anchor, protected signing keys, or cross-host atomicity. Reusing a signed inspection request can produce another read-only inspection, but cannot mutate journal state. An actual recovery protocol must separately specify an independently witnessed monotonic decision and crash-safe state transition; **no repair API is included**. This prototype is Linux-local; no Shopify or network access.
