# Objective 35T — Local artwork pair publication and orphan inspection

Offline local proof service only. A successful upload now stages metadata in a private, exclusive pending file, writes the raster exclusively, then publishes metadata using a no-overwrite hard link. This avoids advertising a completed metadata record when the raster write fails. Failure before publication attempts to remove only files whose creation this operation confirmed; cleanup failures are reported as uncertain rather than claimed successful. A crash or partial write can still leave an image or pending metadata. `inspectLocalArtworkOrphans` reports incomplete pairs, pending metadata, and nonregular entries without deleting or authenticating any files. It does not treat unlisted files as safe, does not guarantee power-loss durability, and does not make the local service a hosted customer-artwork store.

The browser validates the local response's strict allowlisted fields and binds it to the current editor generation. A stale browser response may still leave a complete server-side upload: there is deliberately no unauthenticated DELETE endpoint or automatic sweeping, because another saved draft could reference the artwork and no cross-process reference-counted reclamation protocol exists. Production cleanup, customer ownership, lifecycle retention, quotas, persistence fsync, cross-process coordination, and authenticated garbage collection remain separate unimplemented gates. No Shopify operations or checkout authority.
