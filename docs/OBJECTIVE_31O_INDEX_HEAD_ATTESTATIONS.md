# Objective 31O — Portable acquisition-index attestations and branch review

**Offline diagnostic prototype only.** This module does not operate independent witnesses, retain evidence remotely, establish trusted time, protect keys, authorize recovery, or integrate with Shopify. It must not be treated as hosted authentication, manufacturing approval, payment, cart/checkout/order verification, or permission to acknowledge/retry an ambiguous operation.

## Exports

`src/offline-acquisition-index-attestations.mjs`:

- `offlineAcquisitionIndexAttestationPolicyDigest({witnesses, quorum})`: digest of an independently supplied, strict-majority Ed25519 public-key policy; rejects duplicate IDs and keys.
- `offlineAcquisitionIndexAttestationSigningBytes(body)`: canonical, domain-separated bytes for a receipt body with `schema`, `registryId`, `head`, `previousHead`, `issuedAt`, `expiresAt`, `nonce`, `policyDigest`. The immediate predecessor is required to have count exactly one less than the head. No private keys are stored or generated by the module.
- `verifyOfflineAcquisitionIndexHeadAttestation({attestation, witnesses, quorum, registryId, nowMs})`: validates exact fields, independently trusted witness policy, sorted distinct Ed25519 signatures, quorum, registry binding, receipt lifetime (at most seven days), and caller-provided verification time. Receipt expiration is **not a trusted timestamp**: `nowMs` must come from a trustworthy caller, not the untrusted evidence host.
- `verifyOfflineAcquisitionIndexPortableHistory({history, expectedHead, trustedAnchor})`: checks complete original 31N index records from genesis, index SHA-256 hash-chain, acquisition replay, retention continuity, forensic/publication/outbox monotonicity, exact externally pinned head and a pinned ancestor at the stated height. **Structural check only**: does not verify 31L receipts, 31M sessions, or the original forensic reviewer signatures. Run Objective 31N's full `verify` with the original manifests, pinned session evidence, and independent trust roots separately.
- `reviewOfflineAcquisitionIndexBranches({branches, witnesses, quorum, registryId, nowMs, trustedAnchor})`: checks at least two distinct independently signed receipts and their complete portable index histories. Requires the same independently pinned ancestor and verifies each receipt's immediate predecessor. Returns `SIGNED_BRANCH_EQUIVOCATION_EVIDENCE` with the earliest conflicting index and overlapping witness IDs for incompatible signed branches, or `CONSISTENT_SIGNED_PREFIXES_ONLY` if all histories share their overlapping prefix. The latter does not prove global uniqueness, future consistency, remote retention, or that no unseen competing branch exists.

## Trust and threat boundaries

The `witnesses`, `quorum`, `trustedAnchor`, `registryId`, and `nowMs` inputs **must not be taken from the bundle being verified**. Keys in tests are synthetic. A quorum of signatures means only that holders of those keys signed the specific bytes, not that independent humans or remote services observed the original event. Signed forks are evidence for forensic review, **not authority to choose a winning branch, reconcile, delete, retry, or ACK**. Any mismatch in an externally pinned anchor, signature, policy, or predecessor fails closed. A local attacker can destroy or withhold history; unobserved forks remain undetectable. There is no actual independent witness deployment, key custody, timestamp authority, offsite/WORM retention, or atomic multi-resource recovery.

## Reproduce

```sh
node --test tests/objective31o-index-attestations.test.mjs
node --test --test-concurrency=4 tests/*.test.mjs
```

No network, Shopify, secrets, customer data, dependencies, or production deployment required. Main Engineering's v0.32 UI and the v0.5 2D/3D editor are untouched.
